# CONSUMER PROTECTION ENGINE

## Mission
Transformer une anomalie quotidienne en parcours de protection consommateur.

## Chain
`Detect → Explain → Evidence → Rights/Procedure → Action → Follow-up → Outcome`

## Case types initiaux
- hausse de facture ;
- renouvellement/abonnement ;
- garantie ;
- remboursement attendu ;
- problème de livraison ;
- rappel produit ;
- échéance de contrat ;
- contestation documentée.

## Consumer Evidence Vault
Chaque case doit pouvoir regrouper des preuves : contrat, facture, email, date, réponse, source publique. Le système ne doit pas altérer les originaux ; les versions normalisées sont dérivées.

## Legal safety
Olappus ne se présente pas comme avocat et n'affirme pas automatiquement qu'une entreprise est en infraction. Pour chaque information juridique, afficher la source, la date, la juridiction et le niveau de confiance.

## Action safety levels
0 information ; 1 suggestion ; 2 préparation ; 3 action réversible avec confirmation ; 4 action externe sensible avec confirmation renforcée ; 5 interdite dans le prototype.

## Protection graph
Relations à prévoir :
`merchant ↔ product ↔ contract ↔ price ↔ event ↔ right/procedure ↔ evidence ↔ mediator/authority`.

## Valuable “Why / Prove / Act” flow
Une hausse détectée doit pouvoir devenir un dossier compréhensible en moins de 60 secondes.

## Neutrality rule
Aucune recommandation rémunérée cachée. Toute future monétisation doit préserver l'indépendance de la recommandation consommateur.
