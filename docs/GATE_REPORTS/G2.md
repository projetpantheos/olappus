## RISKS

1. **Le chiffrement applicatif L3 n'est pas implémenté.** `SEC-31` le spécifie — algorithmes, hiérarchie DEK/KEK, rotation — mais aucun champ n'est chiffré aujourd'hui. Aucun champ L3 n'est encore collecté, donc l'écart n'expose rien ; il devra être comblé **avant** le connecteur (G6), qui apportera les premières données L3 réelles.
2. **Les purges ne sont pas encore déclenchées automatiquement.** Le point d'entrée existe, il est testé, et son absence d'exécution est détectable — mais aucun ordonnanceur ne l'appelle. À brancher au déploiement.
3. **La suppression n'est vérifiée que sur les emplacements existants.** Sur les douze de `SEC-33`, six sont couverts ; les autres — SQLite local, outbox, sauvegardes, journaux — n'existent pas encore. Le test devra grandir avec eux, notamment en G8.
4. **La rétention des sauvegardes reste ouverte** (OPEN-06). Tant qu'elle ne l'est pas, la durée après laquelle une donnée supprimée disparaît de **toutes** les copies est inconnue, et ne doit pas être annoncée à l'utilisateur.
5. **`core.retention_policy` duplique le registre.** Un test vérifie leur cohérence, mais la valeur est écrite à deux endroits. Une génération de la migration depuis le registre serait plus sûre — à envisager si le nombre de durées croît.

## CE QUE LES TESTS ONT TROUVÉ

Trois défauts réels, tous détectés par les contrôles eux-mêmes :

1. **Les tests d'isolation ne s'exécutaient pas.** `describe.skipIf` est évalué à la collecte : la variable renseignée dans `beforeAll` restait fausse et les 11 tests se sautaient **en affichant un vert**. Un test qui se saute lui-même est plus dangereux qu'un test absent.
2. **L'audit n'était pas anonymisé.** `SEC-33` le déclarait en `delete: anonymize`, la base ne l'appliquait pas : `actor_id` survivait en clair à la suppression du compte. Le test de suppression l'a révélé, un déclencheur le corrige.
3. **Le validateur de registre a attrapé une erreur de classification** : `core.case.module_id` en L1 avec `AI_ALLOWED`, deux valeurs incompatibles.

Un quatrième, sans conséquence de sécurité : les suffixes juridiques étaient retirés avant la ponctuation, donc « S.A. » devenait « s a » et échappait à la canonicalisation.

## CE QUE LE FONDATEUR DOIT JUGER

- **Valeur produit** : toujours nulle à l'écran, et c'est conforme. G2 construit ce qui rend le reste défendable.
- **Confidentialité** : le registre gouverne, il ne décore pas. Les données de tiers sont traitées, la rétention est chiffrée et purgée.
- **Sécurité** : l'isolation est **démontrée**, pas déclarée. Les schémas sensibles sont inaccessibles par construction, pas par oubli de politique.
- **Provenance** : aucun fait dérivé ne peut exister sans source, version et date.
- **Exploitabilité** : une purge arrêtée est visible ; c'est ce qui distingue une politique d'une intention.
- **Rollback** : trivial.
- **Charge cognitive** : aucune fonctionnalité n'a été ajoutée « pour plus tard ».
